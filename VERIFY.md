## 3. Ranked Likeliest Failure Points in `build-native.sh` & How to Fix Each from Logs

### Rank 1 (Highest Likelihood): `pspp-2.1.2` Cairo / Pango Symbol References During Final Link or `make`
- **Why**: PSPP 2.1.2 does not natively ship a `--without-cairo` configure flag. While `patches/01-disable-cairo-pango.patch` and the `sed` fallback in `build-native.sh` bypass the `PKG_CHECK_MODULES([CAIRO], ...)` check in `configure` and guard `HAVE_CAIRO` in `src/output/driver.c` and `src/output/html.c`, `Makefile.in` may still compile `src/output/cairo.c`, `src/output/charts/plot-hist-cairo.c`, or `src/output/charts/SCATTERPLOT-cairo.c` if `AM_CONDITIONAL([HAVE_CAIRO])` was not regenerated by `autoreconf`.
- **How to read `native-build.log`**:
  - Search for `fatal error: 'cairo/cairo.h' file not found`, `fatal error: 'pango/pango.h' file not found`, or `undefined symbol: xr_driver_create`.
- **How to fix**:
  - Either add `autoreconf -fi` inside `build-native.sh` right after applying patches (since `autoconf`/`automake`/`libtool` are installed in the CI step), OR stub out the 3 headers in `${ABI_PREFIX}/include/cairo/cairo.h` and filter `src/output/cairo.lo` out of `src_libpspp_la_OBJECTS` in `Makefile.in`.

### Rank 2: Gnulib Cross-Compile Checks or Bionic Header Conflicts on `ANDROID_API=24`
- **Why**: PSPP 2.1.2 bundles a large `gl/` (gnulib) directory. When targeting Android API 24 (`__ANDROID_API__ == 24`), some POSIX functions (like `getdtablesize`, `nl_langinfo`, `strchrnul`, or `fseeko`/`ftello`) were added to Bionic only in API 26 or API 28, which can cause gnulib's replacement headers to clash with NDK's `<stdlib.h>` or `<langinfo.h>`.
- **How to read `native-build.log`**:
  - Search for `error: redefinition of` or `error: conflicting types for 'rpl_...'` inside `gl/`.
- **How to fix**:
  - Inspect the failing `gl/<file>.c` line in `native-build.log` and either add the corresponding `ac_cv_func_<name>=yes` / `gl_cv_func_<name>_works=yes` variable to `CONFIG_CACHE` in `build-native.sh`, or bump `ANDROID_API=24` to `ANDROID_API=26` in `build-native.sh` while keeping `minSdk = 24` in Gradle if needed.

### Rank 3: Host Tool Invocations During `make` in `pspp-2.1.2` (`perl` or `texi2any` for Doc Targets)
- **Why**: PSPP's top-level `Makefile` builds both `src/libpspp-core.la` / `src/libpspp.la` and documentation targets (`doc/pspp.info`). Cross-compiling sometimes fails on doc generation even after the C libraries have already been compiled.
- **How to read `native-build.log`**:
  - Look for errors in `doc/` after `CCLD src/libpspp.la` has already succeeded.
- **How to fix**:
  - `build-native.sh` already traps doc-stage failures after `src/.libs/libpspp.a` is built; if `src/.libs/libpspp.a` was not yet built before the error, change `make -j"${JOBS}"` to `make -j"${JOBS}" gl/libgl.la src/libpspp-core.la src/libpspp.la`.

### Rank 4: Duplicate Symbol Definitions When Linking `--whole-archive` into `libpspp_jni.so`
- **Why**: Both `src/.libs/libpspp.a` and `gl/.libs/libgl.a` may include convenience archive members from `gl/`. Using `-Wl,--whole-archive` on both archives can trigger `ld.lld: error: duplicate symbol`.
- **How to read `native-build.log`**:
  - Search for `ld.lld: error: duplicate symbol:` in the `Linking libpspp_jni.so...` section.
- **How to fix**:
  - Add `-Wl,--allow-multiple-definition` to the `${CC} ${CFLAGS} -shared` link command in `build-native.sh` and `app/src/main/cpp/CMakeLists.txt`.
